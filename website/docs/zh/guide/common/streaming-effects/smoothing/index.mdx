# 平滑化

流式文本通常是成批到达的：有时只收到几个字，有时一次收到一整段。平滑化把接收和显示分开，让内容按更连贯的节奏出现在页面上。

## 看见缓冲区

下面的演示模拟大小不同的文本片段陆续到达。正常颜色是已经显示的内容，另一种颜色是已收到、仍在等待显示的缓冲内容。实际应用中，缓冲区里的文字暂时不可见。

<SpringDemo />

新片段到达时，缓冲区先增长，显示边界再逐步跟上。可以暂停观察两者的位置，或重新播放，比较每次收到内容时的变化。

## 弹簧如何调整节奏

内置的 `spring` 追踪器用显示位置和待显示内容之间的距离调整速度。积压内容较多时，输出加快；接近末尾时，速度逐步收敛。它保留前一帧的速度，让后续更新衔接起来。

追踪器按经过的时间计算进度，再把不足一个字符的部分留到下一次更新。这样，文字可以在两次网络更新之间继续显示，也不需要为每个字符设置固定延时。上面的演示使用与 `Smooth` mapper 相同的 `SpringSmoothScheduler`。

## 在应用中使用

React、React Native 和 Lynx 共用这套平滑化算法。以下以浏览器中的 React 组件为例，开启 `streaming` 就会使用默认的弹簧平滑化：

```tsx
<Fluxdown streaming={isStreaming} text={text} />
```

也可以显式指定追踪器，并配合[动画效果](../animation/index.mdx)使用：

```tsx
<Fluxdown
  streaming={{
    smooth: { enabled: true, ticker: 'raf', scheduler: 'spring' },
    effect: 'shad',
  }}
  text={text}
/>
```

`text` 始终传入已经收到的完整内容。将 `streaming` 设为 `false` 后，剩余缓冲会立即显示；如果希望保留收尾过程，可以让平滑化继续开启。

三端都使用 Core 的 `Smooth` mapper，输出经过截取的内容块，渲染层无需自己安排逐字更新。不同的是报时环境：网页跟随浏览器刷新，React Native 使用运行时提供的动画帧，Lynx 在后台线程选择可用的时钟。默认配置在没有动画帧时会改用定时器。

接入方式见 [React Native 流式内容](../../../react-native/streaming.md)、[Lynx 流式内容](../../../lynx/streaming.md)和 [Core 状态与更新](../../../core/streaming.md#启用平滑输出)；共用选项见 [React 配置](../../../react/configuration.md#streamingsmooth)。

## 自己决定更新节奏

平滑化由两部分配合完成：[节奏器](./ticker.mdx)决定什么时候更新，[追踪器](./scheduler.mdx)决定这次向前走多远。前者可以换成固定间隔，后者可以保持匀速，也可以随着积压内容调整。两篇文章各有一组对照演示和一段可直接使用的自定义示例。
