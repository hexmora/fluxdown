# 语法修复 Benchmark - Fluxdown {#语法修复-benchmark}

## 指标定义

每次追加一个 Unicode 码点记为一个输入帧。**跳变帧率**先计算每个样例的「发生跳变的输入帧数 ÷ 输入帧总数」，再对样例等权取平均，以百分比表示；不是汇总所有帧后相除。数值越低，已经展示的内容发生语义切换的频率越低。

同一帧发生多个变化，只计一个跳变帧。最后发送的完成信号帧不计入分子或分母。

### 怎样定义一次跳变

| 相邻两帧发生的变化                                 | 是否计入 |
| -------------------------------------------------- | -------- |
| 新文字第一次出现，已有文字的角色保持不变           | 否       |
| `10` 先显示为正文，随后成为列表编号                | 是       |
| 已显示的正文变成加粗、代码、表格单元格等另一种角色 | 是       |
| 已显示内容被撤回，或撤回后再次出现                 | 是       |
| 原先露出的 Markdown 标记随后被消费、重解释         | 是       |
| 裸 URL 第一次被识别为自动链接                      | 否       |
| 仅发生换行、位置移动、尺寸变化                     | 不测量   |

检测器提取每帧正文字符及其语义祖先（如列表、强调、代码、链接），对齐已经收到的源码字符，再比较前后角色。
