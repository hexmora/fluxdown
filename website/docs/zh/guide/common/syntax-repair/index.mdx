# 语法修复 - Fluxdown {#语法修复}

一段 Markdown 还没接收完，语法就可能停在半个链接、一个列表编号或公式的分母中间。Fluxdown 先呈现已经能确定的结构，暂缓尚不确定的末尾，等后续文字到达后再继续显示。

## 停在任意一个字，看看会发生什么

六个短案例共用一条进度轴。拖动进度、降低速度或单字前进，逐行对照收到的 Markdown、关闭修复与开启修复的结果；点击结束，查看停止末尾修复后的状态。

> 注意内容的“角色”是否改变：数字先作为正文出现、随后变成列表编号，就是一次语法跳变。正常追加文字、换行和公式随新内容变长，不等于语法跳变。

## 当前覆盖哪些语法

下表描述内置修复的主要作用，不表示每一种不完整输入都能提前确定最终含义。

| 语法                 | 流式过程中的处理                                                           |
| -------------------- | -------------------------------------------------------------------------- |
| 加粗、斜体、删除线   | 提前呈现未闭合的格式，处理相邻标记与嵌套；删除线遵循当前语法配置。         |
| 行内代码             | 保留代码语义，支持多反引号边界；代码中的 Markdown 符号不再作为格式修复。   |
| 围栏代码块           | 暂缓不完整的围栏，避免末尾反引号混入代码正文。                             |
| 标题、引用           | 暂缓空标题标记；在引用内继续处理嵌套的文字、列表与代码边界。               |
| 有序、无序与任务列表 | 暂缓不确定的编号、孤立标记与未完成任务框，确定后直接呈现列表结构。         |
| 链接、图片           | 链接先保留可读标签，图片等待完整地址。                                     |
| 引用式链接、脚注     | 处理等待后置定义的引用；定义到达后再连接到对应目标。脚注需开启相应语法。   |
| 表格                 | 暂缓有明确表格迹象的首行与分隔行，继续修复开放单元格里的代码、格式和链接。 |
| HTML                 | 裁掉未完成的标签与属性片段，整理段落和 HTML 的闭合、换行边界。             |
| 转义、字符实体       | 暂缓末尾反斜杠与不完整实体，保留已经转义的字面字符。                       |
| 行内与块级公式       | 识别未闭合的公式边界，再按 KaTeX 校验保留可用的 TeX 前缀。                 |

表格、删除线等修复会检查对应语法是否启用；公式还需要 `build.tex`。完整插件名称与导入路径见 [Core Repair 插件清单](../../core/plugins/repair.mdx#支持的插件)。

## 开启、暂停与结束

| 状态                 | 应用传入什么                                      | 结果                                                       |
| -------------------- | ------------------------------------------------- | ---------------------------------------------------------- |
| 正在生成             | 累积的 `text`，`streaming` 为 `true` 或配置对象。 | 在已启用修复的前提下，默认处理未完成的末尾。               |
| 暂停查看             | 停止追加文字，保持流式状态。                      | 保留当前修复后的展示。                                     |
| 生成结束、取消或失败 | 将 `streaming` 设为 `false`。                     | 停止末尾补全，按实际收到的原文解析；常规边界整理仍可执行。 |

接入方式和各个字段见[编写插件](./plugins.mdx)。
