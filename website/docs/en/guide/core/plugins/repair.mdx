# Repair plugins - Fluxdown Core {#repair-plugins}

Repair plugins post-process the Markdown AST before it becomes HAST. They can repair incomplete syntax, tidy node boundaries, or add temporary presentation without changing the source string.

## Declare a plugin

Add a small indicator after the content while a response is arriving, then remove it when the response finishes:

```ts
import type {
  RepairPluginRunner,
  RepairPluginSystemConfig,
} from '@fluxdown/types';

import { BaseRepairPlugin } from '@fluxdown/core-plugins/plugins/repair/base';
import { PluginPriority } from '@fluxdown/types';

class StreamingIndicatorPlugin extends BaseRepairPlugin {
  static readonly key = 'repair-streaming-indicator';

  readonly config: RepairPluginSystemConfig = {
    ending: true,
    priority: PluginPriority.Lowest,
  };

  readonly runner: RepairPluginRunner = ({ node, break: stop }) => {
    if (node.type !== 'root' || !('children' in node)) {
      return;
    }

    node.children.push({
      type: 'html',
      value: '<span class="indicator"></span>',
    });

    stop();
  };
}

const repairs = [StreamingIndicatorPlugin];
```

After the built-in repairs, this plugin appends an HTML node with the `indicator` class to the current trailing block. `stop()` ends the traversal so it is inserted just once.

## Connect to Core

Add `repairs` to the Core inputs from the [quick start](../quick-start.md), and enable `build.repair` and `build.repairEnding`.

`ending: true` limits the plugin to the last block while it is still being generated. Set `repairEnding` to `false` when the response finishes to remove the indicator. The original Markdown stays unchanged.

The built-in HTML processing already allows the `class` attribute on `span`. With an HTML renderer, a little CSS gives the indicator its shape:

```css
.indicator {
  display: inline-block;
  width: 0.5em;
  height: 0.5em;
  border-radius: 50%;
  background: currentColor;
  opacity: 0.45;
}
```

> Put traversal settings in `config` and keep constructor options in a separate field. Core runs the plugin and manages its lifecycle.

With `ApplyRepairsRemarkPlugin` enabled, the parser records `data.source` on every parsed node. It contains the original Markdown fragment that produced that node. Repairs read this local source directly, without an additional runner parameter or a dependency on node positions.

`data.source` is optional. Hand-built nodes, nodes created by other plugins, and repaired nodes may have no source. Skip checks that require source in that case; substituting `node.value` can mistake escaped characters and decoded entities for syntax.

When a mutation makes the source inaccurate, remove `data.source` from the changed node and affected ancestors while preserving it on unchanged children. The runner clears stale metadata for changes to the current node, its direct children, adjacent siblings, and insertion or replacement operations. Recursive repairs propagate invalidation to outer ancestors. Custom plugins that mutate nodes in lifecycle hooks or directly modify deeper descendants must clear the affected node and ancestor source metadata themselves.

## Supported plugins

Append a subpath from the table to `@fluxdown/core-plugins/plugins/repair/` to import a plugin. For example, `incomplete-image` becomes `@fluxdown/core-plugins/plugins/repair/incomplete-image`.

A check marks plugins included in `PRESET_REPAIR_PLUGINS`, exported from `@fluxdown/core-plugins/presets/repair`. Core registers these automatically; add plugins without a check explicitly.

`build.repair` controls repairs. The first group below handles temporary states at the end of a stream and also requires `build.repairEnding`.

### The streaming tail

| ------------------------------------ | --------------------------- | :-------------: | ---------------------------------------------------------------------------------------------------- |
| `TrailingEscapeRepairPlugin`         | `trailing-escape`           | <PresetCheck /> | Temporarily hides a trailing backslash that has not yet formed an escape sequence.                   |
| `TrailingEmptyCodeBlockRepairPlugin` | `trailing-empty-code-block` | <PresetCheck /> | Hides a trailing code fence that has no language or content yet.                                     |
| `IncompleteCodeFenceRepairPlugin`    | `incomplete-code-fence`     | <PresetCheck /> | Hides unfinished trailing fence backticks so they do not appear inside the code.                     |
| `IncompleteInlineCodeRepairPlugin`   | `incomplete-inline-code`    | <PresetCheck /> | Presents unfinished inline code as code before its closing backtick arrives.                         |
| `IncompleteImageRepairPlugin`        | `incomplete-image`          | <PresetCheck /> | Creates a placeholder for an unfinished image, or hides it with `strategy: 'discard'`.               |
| `IncompleteLinkRepairPlugin`         | `incomplete-link`           | <PresetCheck /> | Presents an unfinished link's text while waiting for the URL to complete.                            |
| `TrailingEmptyHeadingRepairPlugin`   | `trailing-empty-heading`    | <PresetCheck /> | Hides trailing empty headings at levels one through six until their content arrives.                 |
| `IncompleteStrongRepairPlugin`       | `incomplete-strong`         | <PresetCheck /> | Presents bold content before its closing delimiter arrives.                                          |
| `IncompleteEmphasisRepairPlugin`     | `incomplete-emphasis`       | <PresetCheck /> | Presents italic content opened with an asterisk before it is closed.                                 |
| `IncompleteListMarkerRepairPlugin`   | `incomplete-list-marker`    | <PresetCheck /> | Hides a trailing list marker while waiting for the item's content.                                   |

| `DanglingFootnoteRepairPlugin`       | `dangling-footnote`         | <PresetCheck /> | Temporarily hides unresolved and incomplete trailing footnote references; requires `build.footnote`. |

### Holding an unfinished table header

A trailing line beginning with an unescaped `|` is held temporarily. It appears as a table once a valid delimiter row arrives, or returns as ordinary text when subsequent input rules out a table. Text without a leading pipe, such as `a | b`, stays visible until the next line begins a possible table delimiter.

This repair requires `repairEnding`. Disable it when streaming finishes to restore text that never became a table. Disabling `remark-syntax-table` also disables this repair. Escaped pipes, character entities, and complete inline code do not independently trigger header holding.

### Formatting boundaries

These plugins run when `build.repair` is enabled and do not require `repairEnding`.

| Plugin                                 | Subpath                       |    Built in     | Purpose                                                                       |
| -------------------------------------- | ----------------------------- | :-------------: | ----------------------------------------------------------------------------- |
| `IncompleteHtmlTagRepairPlugin`        | `incomplete-html-tag`         | <PresetCheck /> | Hides an unfinished HTML tag fragment at the end of the content.              |
| `RedundantBreakBeforeHtmlRepairPlugin` | `redundant-break-before-html` | <PresetCheck /> | Removes redundant line-break nodes before HTML fragments.                     |
| `HtmlBoundaryLineBreakRepairPlugin`    | `html-boundary-line-break`    | <PresetCheck /> | Preserves intended line breaks where text meets HTML.                         |
| `ParagraphHtmlClosureRepairPlugin`     | `paragraph-html-closure`      | <PresetCheck /> | Closes HTML tags in completed paragraphs so they do not affect later content. |
| `RedundantTrailingBreakRepairPlugin`   | `redundant-trailing-break`    | <PresetCheck /> | Removes redundant trailing line breaks.                                       |
| `AdjacentTextRepairPlugin`             | `adjacent-text`               | <PresetCheck /> | Merges adjacent text and removes empty text after repairs.                    |

Repairs affect the current presentation, not the original Markdown stored by your app.
