# Rehype plugins

Rehype plugins post-process HAST, the HTML syntax tree produced from Markdown. Use them to change element properties or normalize HTML before rendering.

## Declare a plugin

This plugin uses image descriptions as hover titles:

```sh
pnpm add @fluxdown/core-plugins
pnpm add -D @types/hast unified
```

```ts
import type { Root, RootContent } from 'hast';
import type { Plugin } from 'unified';

import { BaseRehypePlugin } from '@fluxdown/core-plugins/plugins/rehype/base';

class ImageTitlesPlugin extends BaseRehypePlugin {
  static readonly key = 'rehype-image-titles';

  readonly plugin: Plugin<[], Root> = () => (tree) => {
    function visit(node: Root | RootContent) {
      if (node.type === 'element' && node.tagName === 'img') {
        const { alt, title } = node.properties;

        if (typeof alt === 'string' && !title) {
          node.properties.title = alt;
        }
      }

      if ('children' in node) {
        node.children.forEach(visit);
      }
    }

    visit(tree);
  };
}

const rehypes = [ImageTitlesPlugin];
```

Add `rehypes` to the Core inputs from the [quick start](../quick-start.md). The transform runs again when a content block is recompiled.

> The default sanitizer still processes the output. Properties and tags added by a plugin must be allowed by its schema.

## Allow additional HTML tags

Embedded HTML passes through both syntax filtering and HAST sanitization. Configure both stages to allow an extra tag, such as `mark`:

```ts
import { toClosure } from 'stative';

const remarks = toClosure<RemarkConfigs>({
  'remark-syntax-html-allowed': {
    enabledTags: ['mark'],
  },
});

const rehypes = toClosure<RehypeConfigs>({
  'rehype-sanitizer': {
    allowedTags: ['mark'],
  },
});
```

`toClosure` turns each configuration object into a readable Core input. Pass both `remarks` and `rehypes` to Core. These options extend the existing tag lists. Use the sanitizer's `fallback` schema to allow additional attributes.

### Pass options with a plugin class

You can express the same configuration as `[PluginClass, options]`. Core passes the options to the constructor and manages the instance:

```ts
import type { IPluggable, IRehypePlugin, IRemarkPlugin } from '@fluxdown/types';

import { SanitizerRehypePlugin } from '@fluxdown/core-plugins/plugins/rehype/sanitizer';
import { SyntaxHtmlAllowedRemarkPlugin } from '@fluxdown/core-plugins/plugins/remark/syntax-html-allowed';

type RemarkPlugin = IPluggable<IRemarkPlugin, unknown>;
type RehypePlugin = IPluggable<IRehypePlugin, unknown>;

const remarks: RemarkPlugin[] = [
  [SyntaxHtmlAllowedRemarkPlugin, { enabledTags: ['mark'] }],
];

const rehypes: RehypePlugin[] = [
  [SanitizerRehypePlugin, { allowedTags: ['mark'] }],
];
```

Choose keyed options to keep built-in configuration together, or class tuples to register and configure plugins in one place. Pass the class; Core creates the instance.

## Supported plugins

Append a subpath from the table to `@fluxdown/core-plugins/plugins/rehype/` to import a plugin. For example, `sanitizer` becomes `@fluxdown/core-plugins/plugins/rehype/sanitizer`.

A check marks plugins included in `PRESET_REHYPE_PLUGINS`, exported from `@fluxdown/core-plugins/presets/rehype`. Core registers these automatically; add plugins without a check explicitly.

| Plugin                      | Subpath          |    Built in     | Purpose                                                                            |
| --------------------------- | ---------------- | :-------------: | ---------------------------------------------------------------------------------- |
| `HoistFootnoteRehypePlugin` | `hoist-footnote` |                 | Moves the final footnote section into `tree.data.footnote` for separate rendering. |
| `RawParserRehypePlugin`     | `raw-parser`     | <PresetCheck /> | Parses allowed raw HTML into HAST nodes alongside Markdown-generated content.      |
| `SanitizerRehypePlugin`     | `sanitizer`      | <PresetCheck /> | Cleans HTML output according to allowed tags, attributes, and protocols.           |

`RawParserRehypePlugin` and `SanitizerRehypePlugin` work together to handle HTML embedded in Markdown. See [Allow additional HTML tags](#allow-additional-html-tags) for an example.
