# Driver - Fluxdown {#driver}

Smoothing answers two questions: **when to update, and how much to reveal.** The driver handles the first; the [interpolation](./interpolation.mdx) handles the second.

In a browser, the default driver follows animation frames. Keep that default unless you want fewer updates or need to use a clock supplied by your host environment.

## Slow down the ticks

Both sides receive the same text and use the same spring interpolation. Try `320 ms` on the right: text arrives in visible steps. At `50 ms`, those steps become smaller.

The Received bar advances as each batch arrives. Between batches, the text below can keep unfolding. Click the output area to bring the next batch forward.

Fewer ticks can mean more progress per tick. A driver does not directly set the reading speed: the spring interpolation calculates progress from elapsed time and the waiting content.

## Use a built-in driver

`'raf'` follows `requestAnimationFrame`, which suits continuous browser rendering. `'interval'` uses a timer, ticking about every 16.7 milliseconds by default. With `smooth: true`, Fluxdown chooses an available driver automatically.

Here is the React configuration. Other frameworks accept the same options through `streaming.smooth`:

```tsx
<Fluxdown
  streaming={{
    smooth: { enabled: true, driver: 'raf', interpolation: 'spring' },
    effect: false,
  }}
  text={text}
/>
```

Entry effects are disabled here so the update interval is easier to see. You can still combine smoothing with [animation effects](../animation/index.mdx).

## Choose an interval

You do not need to write a timer just to change its frequency. Extend `IntervalSmoothDriver` and pass an interval to its constructor. This is the `160 ms` option in the demo:

```tsx
import { IntervalSmoothDriver } from '@fluxdown/core-plugins/plugins/mapper/smooth';
import { Fluxdown } from 'fluxdown';

class SlowDriver extends IntervalSmoothDriver {
  constructor() {
    super(160);
  }
}

export function Message({ text }: { text: string }) {
  return (
    <Fluxdown
      streaming={{
        smooth: { enabled: true, driver: SlowDriver, interpolation: 'spring' },
        effect: false,
      }}
      text={text}
    />
  );
}
```

Pass the **class**, not `new SlowDriver()`. Fluxdown creates the instance, stops it when the content has caught up and the interpolation permits it, restarts it for new content, and cleans it up when the component is destroyed. Keep the class outside your component so each render does not replace it.

## Connect another clock

If your host provides its own frame callbacks, extend `BaseSmoothDriver` and supply these members:

| Member    | Responsibility                                                 |
| --------- | -------------------------------------------------------------- |
| `running` | Whether the driver is currently emitting timestamps.           |
| `start()` | Subscribe to the host clock and return the starting timestamp. |
| `stop()`  | Cancel callbacks and stop emitting timestamps.                 |
| `now()`   | Read the current time in milliseconds.                         |

In each callback, emit its timestamp with `this.subject.next(timestamp)`. The return values of `start()` and `now()` and the emitted timestamps must share one clock origin. Do not mix wall-clock time with time measured since the page started. The base class's `destroy()` stops a running driver and completes its observable.

To change how fast the text catches up, or reveal a fixed number of units at a time, continue to [Interpolation](./interpolation.mdx).
