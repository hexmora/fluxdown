# Smoothing - Fluxdown {#smoothing}

Streaming text usually arrives in bursts: a few characters in one update, a whole paragraph in the next. Smoothing separates receiving content from displaying it, so those updates appear at a steadier pace.

## Tracking progress

This demo receives text in chunks of different sizes. The normal text color marks content already displayed; the other color marks received content still waiting in the buffer. In an application, the buffered text is not visible yet.

<SpringDemo />

When a chunk arrives, the buffer grows first and the visible boundary follows. Pause playback to hold both positions for inspection, or replay to watch how each incoming chunk changes the pace.

## Smoothing with spring mechanics

Imagine a spring pulling the visible position toward the received content. As new content moves the target forward, the gap stretches the spring. A larger gap produces a stronger pull:

<SpringEquation />

Here, `r` is the target, `x` the current position, `k` the spring stiffness, and `m` the mass. Distance changes the force, which changes the velocity. The position does not jump simply because the target has moved.

Fluxdown uses this idea to track reveal progress. A large batch increases the gap, so output accelerates. Each update keeps the previous velocity, connecting one burst to the next. The implementation also adjusts the pulling target using a small buffer and limits the minimum and maximum speed. Speed can fall near the end and continues to decay after catching up. The visible position only moves forward and never passes the received content.

<SpringCurve />

> The stepped line shows content arriving in batches; the curve shows visible progress. The curve is sampled directly from the current `SpringSmoothScheduler`. When the steps pause, the visible position keeps catching up. Replay to watch what happens each time the gap grows.

This suits an uneven stream: small arrivals can join the existing pace, while a large backlog encourages the output to catch up. The scheduler calculates progress from elapsed time, without a fixed delay for each character.

## Two parts of smoothing

Smoothing has two parts: a [ticker](./smoothing/ticker.mdx) decides when to update, and a [scheduler](./smoothing/scheduler.mdx) decides how far to advance.

<SmoothingPartsDiagram />

> At the 160 ms tick, the target is 8. The scheduler advances the visible position by 2, from 3 to 5. The ticker decides when to update; the scheduler decides how far to move.

The defaults suit most streams. Replace either part when you need a fixed interval, a fixed step, or a host-specific clock. Both guides include comparisons and working examples.

## Use it in your application

Choose your framework above each example. Pass the Core example’s `mappers` to the [Core inputs](../../core/quick-start.md); Core produces content and effect markers, while your renderer supplies their appearance. The components include those renderers.

Enabling `streaming` uses spring smoothing by default:

<FrameworkCodeTabs frameworks={['Core', 'React', 'Vue', 'Svelte', 'Angular', 'React Native', 'React Lynx', 'Vue Lynx', 'Solid', 'Taro', 'uni-app']}>

```ts
import type { MapperPluggable } from '@fluxdown/core';
import { Smooth } from '@fluxdown/core-plugins/plugins/mapper/smooth';
import { Scale } from '@fluxdown/core-plugins/plugins/mapper/scale';
import { MutableState, toClosure } from 'stative';

const isStreaming = MutableState.of(true);
const active = toClosure(isStreaming);

const mappers: MapperPluggable[] = [
  [Smooth, { enabled: active }],
  [Scale, { enabled: active }],
];
```

```tsx
import { Fluxdown } from 'fluxdown';

type MessageProps = {
  text: string;
  isStreaming: boolean;
};

export function Message({ text, isStreaming }: MessageProps) {
  return <Fluxdown streaming={isStreaming} text={text} />;
}
```

```vue
<script setup lang="ts">
import { Fluxdown } from '@fluxdown/vue';

defineProps<{ text: string; isStreaming: boolean }>();
</script>

<template>
  <Fluxdown :streaming="isStreaming" :text="text" />
</template>
```

You can also select the scheduler explicitly and add an [animation effect](./animation/index.mdx):

<FrameworkCodeTabs frameworks={['Core', 'React', 'Vue', 'Svelte', 'Angular', 'React Native', 'React Lynx', 'Vue Lynx', 'Solid', 'Taro', 'uni-app']}>

```ts
import type { MapperPluggable } from '@fluxdown/core';
import {
  RafSmoothTicker,
  Smooth,
  SpringSmoothScheduler,
} from '@fluxdown/core-plugins/plugins/mapper/smooth';
import { Shad } from '@fluxdown/core-plugins/plugins/mapper/shad';

const mappers: MapperPluggable[] = [
  [
    Smooth,
    {
      enabled: true,
      ticker: RafSmoothTicker,
      scheduler: SpringSmoothScheduler,
    },
  ],
  [Shad, { enabled: true }],
];
```

```tsx
import { Fluxdown } from 'fluxdown';

type MessageProps = {
  text: string;
};

export function Message({ text }: MessageProps) {
  return (
    <Fluxdown
      streaming={{
        smooth: { enabled: true, ticker: 'raf', scheduler: 'spring' },
        effect: 'shad',
      }}
      text={text}
    />
  );
}
```

<script setup lang="ts">

Always pass the complete text received so far to `text`. Setting `streaming` to `false` reveals the remaining buffer immediately. Keep smoothing enabled if you want the remaining content to finish appearing gradually.

Core uses the same `Smooth` mapper to produce trimmed content blocks, so the renderer does not need to schedule character updates. See [Core state and updates](../../core/streaming.md#enable-smooth-output) for integration and your framework’s configuration for all options: [React](../../react/configuration.md#streamingsmooth), [Vue](../../vue/configuration.md#streamingsmooth), [Svelte](../../svelte/configuration.md), [Angular](../../angular/configuration.md#streamingsmooth), [React Native](../../react-native/configuration.md), [React Lynx](../../react-lynx/configuration.md), [Vue Lynx](../../vue-lynx/configuration.md), [Solid](../../solid/configuration.md#streamingsmooth), [Taro](../../taro/configuration.md), or [Uni App](../../uni-app/configuration.md#streamingsmooth).
